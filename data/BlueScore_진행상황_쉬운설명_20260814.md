# 작성: 오동규

# 지금까지 뭘 했고, 앞으로 뭘 할지 (쉬운 설명, 2026-08-14)

BlueScore는 배 한 척마다 두 가지를 보고 점수를 매기는 서비스입니다 —
"이 배가 어장을 얼마나 혹사시키는가"(A축)랑 "이 배가 연료를 효율적으로
쓰는가"(B축). 여기 정리한 건 그 계산 로직(score/)과, 그걸 돌리는 데 필요한
데이터(data/) 작업이 지금 어디까지 왔는지에 대한 설명입니다.

## 오동규가 한 일

### 1. 점수 계산 로직 만들기 (score/)

- **A축**: "같은 어장을 자주 가는가" + "그 어장이 원래 붐비는 곳인가" 두
  가지로 압력을 계산합니다. 만들다 보니 처음엔 "나 혼자 자주 가는 것"도
  "혼잡한 곳에 간 것"처럼 잘못 계산되는 버그가 있었는데 고쳤습니다.
  그리고 "혼잡한 곳을 반복해서 가는 건 더 나쁘다"는 논리도 추가했습니다.
- **B축**: "이 배가 물리적으로 얼마나 연료를 썼을지" 계산하는 물리 공식이
  원래 있었는데, 여기에 "비슷한 조건의 다른 배들은 보통 얼마나 쓰는지"
  예측하는 AI(LightGBM)를 붙여서, 그 차이(잔차)로 운항 효율을 판단하게
  만들었습니다.

### 2. 국내 정부 API 연동 고치기

선박 정보를 가져오는 국내 API(선박제원정보)가 있었는데, 원래 코드는
실제로 호출해본 적 없이 "이런 주소, 이런 항목일 것 같다"고 추측만 해둔
상태였습니다. 실제 키로 직접 호출해보니 주소도 틀렸고 항목 이름도 다
틀려서 전부 고쳤습니다. 이 과정에서 **"이 API엔 MMSI(선박 고유번호)가
없다"**는 중요한 사실도 발견했습니다 — 배 매칭할 때 호출부호나 IMO번호
같은 다른 식별자를 써야 한다는 뜻입니다.

### 3. 김태윤님이 멈춰있던 작업 이어받기

김태윤님이 선박정보를 수집하다가 API 하루 사용량을 다 써서 63.6%에서
멈춰있었는데, 오동규 API 키로 이어받아서 나머지를 전부 받았습니다.
그리고 그 새 데이터로 "어느 국내 배가 어느 GFW 배랑 같은 배인지"
매칭하는 것도 다시 돌려서 숫자를 갱신했습니다.

김태윤님이 남긴 요청 문서(`팀원_요청_선박제원_재수집_20260814.md`)의
순서 그대로 보면:

1. 저장소 최신 상태 받기 — ✅ 완료
2. `.env`에 API 키 설정 확인 — ✅ 완료 (처음엔 저장이 안 돼있어서 다시
   저장하시게 안내한 뒤 확인함)
3. 수집 스크립트 실행해서 이어받기 — ✅ 완료 (중간부터 이어받아서 끝까지,
   에러 0건)
4. 다 되면 커밋/푸시 — ⚠️ **커밋까지만 완료, 푸시는 오동규가 직접 할 예정**
5. (참고) 끝나면 매칭 스크립트들도 다시 돌리기 — ✅ 완료 (매칭된 배
   숫자 갱신함)

즉 5단계 중 4단계는 끝났고, 마지막 푸시 한 단계만 남아있습니다.

### 4. 새 데이터 활용할 준비 (로더 2개 추가)

이미 다운받아져 있었지만 아무 코드도 안 쓰고 있던 파일 2개를 실제로
읽을 수 있게 만들었습니다:
- **해역별·시간대별 실제 선박 척수 통계** — 나중에 A축 혼잡도 계산을
  더 정확하게 만드는 데 쓸 수 있는 공식 자료
- **업종별 마력 통계** — 개별 선박의 엔진 출력을 모를 때 대신 쓸 수
  있는 보정 자료

## 태윤님이 이제 할 일

1. **오동규가 만든 것들을 git으로 받기** (push되면 pull)
2. **해양기상 데이터를 실제 조업 이벤트에 붙이는 작업** — API 연결은
   이미 검증됐는데, 91만 건이나 되는 이벤트에 실제로 날씨 정보를 붙이는
   큰 작업이 아직 안 됐습니다. 선박 매칭이 막 끝났으니 지금이 시작할
   타이밍입니다.
3. **연안 AIS 통계 API 승인 기다리기** — 본인이 할 수 있는 게 없고
   그냥 승인 나길 기다려야 합니다.
4. **국내 어업 종류를 GFW 분류에 맞게 대응표 만들기** — 자동으로 될 수
   없는 작업이라 사람이 직접 19개 종류를 하나씩 대조해야 합니다. 다만
   태윤님 혼자 정할 일은 아니고, 팀이 같이 논의해서 확정해야 하는
   사안입니다.
5. **score/ 폴더는 손대지 않기** — 그건 김준기·오동규 담당이니, 태윤님은
   데이터 준비(data/)에만 집중하면 됩니다.
