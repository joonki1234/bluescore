## 2. 확정된 제품 범위 (2026-08-17)

### 시연 페르소나

1. **개선형 어업인** — 현재 BlueScore 우대구간 B인 선박이 개선 시뮬레이터에서
   재방문 횟수·항해속도를 조정하고, A구간 진입 가능성과 예상 금리우대를 확인한다.
2. **이의제기 어업인 + 금융기관 심사역** — 지속가능성 위험 신호로 C구간을 받은
   차주가 점수 근거·데이터 출처·실측/추정 여부를 확인하고 이의제기한다. 심사역은
   리포트와 근거를 검토해 승인/보류를 결정한 뒤 최종 리포트 해시를 온체인에
   커밋하고 기록을 조회한다.

낮은 점수를 고의·불법과 동일시하지 않는다. 화면과 발표에서는 "악성 어업인" 대신
"지속가능성 위험 신호가 높게 관측된 선박" 또는 "C구간 이의제기 차주"라고 표현한다.

### 데이터·AI·체인 범위

- 시연 선박은 실제 선박으로 오인되지 않도록 **실데이터 분포를 반영한 가명·시연용
  선박**으로 고정한다.
- 발표 당일 외부 데이터 API는 호출하지 않는다. 버전이 고정된 로컬 스냅샷을 쓴다.
- 점수·시뮬레이션 숫자는 `score/`가 계산하고, `explain/`은 쉬운 문장으로만 바꾼다.
- RAG는 붙이지 않는다. 요인 코드별 허용 개선팁을 작은 규칙 테이블로 관리한다.
- LLM 설명은 사전 생성·검증·캐시하고, 실시간 호출 실패 시 템플릿 폴백을 쓴다.
- 블록체인은 **온체인 커밋·조회·해시 기록**만 시연한다. 변조 검증 UI는 만들지 않는다.
- 원본 항적·개인정보·이의제기 본문은 온체인에 올리지 않는다.

## 5. 설계 원칙

- **FastAPI는 프론트엔드가 아니라 애플리케이션 백엔드다.** 프론트는 확정된 API
  계약만 소비하고 점수·해시를 직접 계산하지 않는다.
- **SQLite는 마지막 부가기능이 아니다.** 이의제기·심사·온체인 기록을 잇는 업무
  상태의 기준 저장소이므로 API 구현 전에 스키마를 고정한다.
- **LLM은 숫자와 개선효과를 만들지 않는다.** `score/`가 만든 사실과 허용된 개선팁을
  어업인이 이해할 수 있는 문장으로 바꾸는 역할만 한다.
- **블록체인은 DB를 대체하지 않는다.** 상세 리포트와 이의제기·심사 이력은 SQLite에,
  최종 리포트 해시와 기록시각은 온체인에 둔다.
- **시연 결과는 결정론적이어야 한다.** 외부 데이터·LLM 호출 장애가 있어도 고정
  스냅샷과 검증된 캐시·폴백으로 두 시나리오가 끝까지 진행돼야 한다.
