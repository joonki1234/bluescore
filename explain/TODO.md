### (2) 설명 계층 — `explain/` (2026-08-14, **아직 미커밋**)

- **설계 변경 — 기여도 계산은 `score/`가, 문장화만 `explain/`이 한다.**

  정반대 조언을 하는 것을 막았다.
- `render.py` — Strict JSON 파싱 + **숫자 창작 검증**(`find_invented_numbers`).

- `fallback.py` — LLM 없이도 화면이 비지 않는 템플릿. 한국어 조사(이/가) 처리 포함.
- `facts.py` — RAG 대신 쓰는 고정 사실 테이블. 확정 7건 / 확인 대기 4건.
- `provider.py` + `providers/` — 프로바이더 중립 구조. OpenAI 구현 완료,
  앨런은 스텁.
- `explain.py` — **절대 예외를 던지지 않는다.** 어떤 실패든 폴백으로 흡수하고
  사유를 `source`에 남긴다.
- 화면 연결 — `adapter.explanation()` → 어업인 화면 3번 탭. LLM 생성인지 폴백인지
  화면에 표시(`components.explanation_source`).
- **심사역 화면 연결** — 2번 탭 '산출 근거 요약'이 mock의 고정 문자열
  (`vessel["summary"]`) 대신 `explain/` 생성 문장을 쓴다. 선박당 한 번만 생성해
  캐시하므로 두 화면이 **같은 문장**을 본다 — 화면마다 다른 설명이 나오면
  "제3자가 관측한 동일한 점수"라는 전제가 문장 층에서 깨진다. LLM/폴백 구분도
  함께 표시한다. 심사역에게는 이 구분이 심사 근거의 출처 정보다.
  개선 코칭은 노출 범위표대로 여기 두지 않았다.

## 3. 시연 제안 — 무엇을 보여줄 것인가 

### 문제 인식

기획서의 3분 시나리오(① 선택 → ② 점수 → ③ 2축 → ④ 설명 → ⑤ 슬라이더 → ⑥ 리포트)는
**기능 투어**다. 순서대로 잘 도는데, 심사위원이 그날 보는 대시보드 20개가 전부
같은 구조로 돈다. 기능이 많다는 것은 기억에 남지 않는다.

우리 차별점 5가지 중 화면이 실제로 **증명**하는 것은 ④(개선 경로) 하나뿐이다.
①제3자 관측 ②상시 산출 ⑤변조 불가는 지금 전부 **글자로 적혀 있을 뿐**이다.
적힌 주장은 심사위원이 안 믿는다.

### 제안 — "공격해 보세요" 구성

기능을 보여주는 대신, **이 서비스를 무너뜨릴 방법 네 가지를 심사위원에게 먼저
건네고 전부 막히는 것을 보여준다.** 방어가 되는 서비스는 기능이 많은 서비스보다
오래 기억에 남고, 무엇보다 Q&A에서 나올 질문을 발표가 선점한다.

| # | 심사위원이 의심할 것 | 무너뜨리는 장면 | 지금 상태 |
|---|---|---|---|
| ① | "점수 그거 고치면 되잖아" | 해시 대상 원문의 점수를 그 자리에서 고침 → 해시가 통째로 바뀌고 **검증 실패** 표시 | 해시 구현됨, **검증 UI 없음** |
| ② | "AI가 지어낸 숫자 아니냐" | 설명 문장의 모든 수치에 밑줄 + "계산 결과와 대조 완료 7/7" 배지. 지어낸 응답을 일부러 넣어 **폴백으로 강등되는 것**까지 시연 | 검증 로직 있음, **화면에 안 보임** |
| ③ | "슬라이더 끝까지 밀면 만점이겠네" | 밀어보게 함. **최고점은 중간에 있고** 끝에서는 떨어진다 | 반작용 반영됨, **곡선이 안 보임** |
| ④ | "데이터 없는 배는 어쩌나" | 선박 D·E 선택 → 점수가 사라지고 사유·다음 조치가 뜸 | **이미 완성** |

②③④는 이미 만든 것 위에 표시만 얹으면 되고, ①만 새로 만들면 된다.

### 가장 임팩트 있는 한 장면

**①번, 심사위원이 직접 점수를 고치는 장면**을 절정에 놓는다.

심사역 화면의 `해시 대상 원문 보기`를 펼쳐 `blueScore: 72.6`을 `92.6`으로 바꾸게
하고, `검증` 버튼을 누르면 기록된 해시와 불일치가 뜨는 구성이다. 3초면 이해되고
말이 필요 없다. 그린워싱을 "구조적으로 차단한다"는 문장 한 줄보다, 심사위원이
직접 조작해 실패하는 3초가 압도적으로 세다.

여기에 **온체인 커밋(`chain/`)이 붙으면 완성된다** — 트랜잭션 해시와 블록 번호가
화면에 뜨고, 그 값은 우리 코드가 아니라 체인에 있다. "너희가 만든 화면이니까
너희 마음대로 아니냐"는 반박까지 닫힌다.

### 두 번째 — 두 화면 동시 표시

어업인 폰 화면과 심사역 데스크 화면을 **한 슬라이드에 나란히** 띄우고 선박을
바꾼다. 두 화면의 숫자가 같이 움직이는데 보여주는 것은 완전히 다르다.
"같은 관측, 다른 시선"이 설명 없이 전달되고, 어업인 화면이 폰 프레임 안에 있으면
"이건 데모가 아니라 서비스"라는 인상이 붙는다. 비용은 거의 없다 —
시연 전용 페이지에서 `iframe` 두 개(375px / 1280px)를 나란히 놓으면 된다.

### 세 번째 — 지도로 A축을 설명

지금 지도는 이벤트 점과 점선 항적만 보여준다. 여기에 **격자 재방문 히트맵**을
얹으면(기획서 8-2 ②에 이미 있다) "같은 자리를 계속 긁었다"가 그림 하나로 끝난다.
A축이 무엇을 재는지 말로 설명할 필요가 없어지고, 선박 B(56.9)와 선박 C(84.8)를
나란히 놓으면 점수 차이가 항적 패턴 차이로 눈에 보인다.

## 4. 그래서 무엇을 더 만들 것인가

우선순위 순. 위 시연 구성에 필요한 것만 적었다.

### P0 — 발표 전 반드시

1. **해시 검증 UI** (`ui/bank.py` + `adapter.verify_hash()`)
   원문 편집 → 재계산 → 일치/불일치 배지. 반나절.
   `chain/`이 늦어져도 로컬 해시만으로 성립하므로 남을 기다리지 않는다.
2. **숫자 검증 결과를 화면에 노출** (`explain/contract.py` + `render.py`)
   지금 검증 통과 정보가 그냥 버려진다. `ExplainOutput`에 대조한 수치 개수와
   목록을 실어 화면에 배지로 띄운다. 두세 시간.
3. **실산출 1척** — A축은 GFW 이벤트만 있으면 계산된다(데이터 현황 문서 기준
   "바로 실행 가능"). B축이 막혀 있으니 **A축 실산출 / B축 잠정**의 혼합 상태를
   화면이 구분해 표시하게 한다. 지금처럼 하단에 "mock 임시값"이 발표 내내 떠
   있으면 그 자체가 감점이다. 축별 산출 경로 표시로 바꾼다.

### P1 — 있으면 확실히 세진다

4. **시뮬레이터 점수 곡선** — 슬라이더 전 구간을 스윕해 점수 곡선과 **최적점**을
   같이 그린다. 시뮬레이터가 "예상 계산기"에서 "조업 처방"으로 격상된다.
   `adapter.simulate`를 격자로 돌리기만 하면 되고, 계수가 잠정값이라는 표기는
   유지한다.
5. **시연 전용 병렬 화면** (`ui/demo.py`) — 폰 프레임 + 데스크 화면 나란히.
6. **격자 재방문 히트맵** — Leaflet 사각형 오버레이. 격자 크기는 미확정
   파라미터라 설정값으로 뺀다.

### P2 — 여유가 있으면

7. **온체인 커밋 표시** — `chain/`이 나오면 트랜잭션 해시·블록 번호를 심사역
   화면에 노출. ①번 장면의 완성형.
8. **어업인 화면 모바일 레이아웃 정리.**
9. **6개월 추이 애니메이션** — "상시 산출"을 시각적으로 증명. `trend` 데이터는
   이미 있다.

### 만들지 않을 것

- **RAG.** 입력이 전부 계산된 숫자라 LLM이 할 일은 검색이 아니라 문장화다.
  법령 텍스트를 검색해 넣으면 조항을 틀리게 말할 위험이 새로 생긴다. 법령 지식이
  필요한 자리는 `facts.py`가 덮는다. 벡터 DB도 임베딩도 필요 없고 결정론적이라
  감사가 된다.
- **음성·챗봇 인터페이스.** 기획서 설계 원칙이 "입력이 하나다"인데 대화형을
  붙이면 그 원칙을 스스로 깬다.
- **발표 당일 라이브 API 호출.** 네트워크에 데모를 건다. 수집 시각을 화면에
  표기하는 것으로 대체한다.

## 5. 설계 메모

**숫자 검증이 설명 계층의 핵심이다.** 기획서 (8-3)의 "숫자를 창작하지 않도록
계산 결과를 프롬프트에 주입하고 문장 생성만 맡긴다"는 프롬프트만으로는 보장되지
않는다. 프롬프트는 부탁이고 `render.py`는 검사다. 응답에 입력에 없던 수치가
섞이면 그 응답은 버리고 폴백으로 강등한다. 위 시연 구성 ②번은 이 코드를 화면으로
꺼내는 일일 뿐, 새 기능이 아니다.

**폴백을 먼저 만들었다.** LLM이 없어도 화면이 비지 않는다. 발표 당일 API가 죽어도
데모가 멈추지 않게 하려는 것이다. 같은 이유로 앨런 회신 여부에 일정을 걸지 않는다.

**정직한 표기가 감점이 아니라 득점이 되게 한다.** 산출 경로 표시, 90% 구간,
"잠정값" 표기는 숨기면 지적당하고 드러내면 심사위원이 물어볼 질문을 화면이 먼저
답한다. 다만 `mock 임시값`이 발표 내내 떠 있는 것은 정직함이 아니라 미완성이므로,
P0 3번으로 축별 표기로 바꾼다.
